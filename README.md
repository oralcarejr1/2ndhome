# 2ndhome — 이사 갈 집 3D 인테리어 플래너

이사 갈 집의 평면도 위에 **실제 판매 제품 치수로 만든 3D 가구**를 놓아 보고, 여러 배치안을 **버전**으로 저장·비교하고, **무드보드**로 분위기를 모으고, 함께 살 사람의 **키 기준으로 쓰기 편한지** 확인하는 웹앱입니다.

처음 열면 **샘플 원룸**이 열려요. 내 집은 2D 평면에서 벽·문·창을 그리거나(분양 도면 이미지를 깔고 따라 그리기 가능), 다른 곳에서 내보낸 **백업 파일을 복원**(버전 탭 → 백업 파일 복원)해서 가져와요. 백업 파일에는 그 집의 도면·실측 메모·붙박이·구매 후보 목록·배치안·무드보드가 모두 들어 있어요.

**집 데이터는 이 저장소에 없어요.** 코드는 앱과 일반 카탈로그, 샘플 원룸뿐이고, 실제 집의 데이터는 비밀번호로 잠긴 서버(또는 백업 파일)에만 있어요.

화면 구성: 상단 **3D 공간 / 2D 평면 / 1인칭 체험 / 무드보드**, 왼쪽 **가구 후보 · 배치목록 · 사람·동선 · 버전저장** 탭, 오른쪽 **속성(공간 마감 & 환경)** 패널, 하단 카메라 바(전체 3D · 창가 뷰 · 현관→거실 · 책상·붙박이장 · 탑뷰). 가구 관리(실제 제품 카탈로그·직접 등록·3D 파일·후보 교체·형태/소재 편집)와 3D 모델링은 파라메트릭 생성기를 씁니다.

## 주요 기능

| 영역 | 내용 |
| --- | --- |
| **평면도** | 벽·문(여닫이/양개/미닫이)·창·발코니창·방을 그리고 수치로 편집. 분양 도면 이미지를 깔고 두 점으로 축척 맞추기. 천장 높이, 문 여는 방향·경첩 위치, 현관 지정 |
| **가구 배치 (3D)** | 3D 궤도 보기 · 위에서 보기(탑뷰) · 1인칭(사람 눈높이로 걷기, 벽·가구 충돌) |
| **배치 방식** | 끌어서 이동, 고리로 회전(15° 스냅/자유), 벽에 딱 붙기, 다른 가구 모서리 정렬 가이드, 격자 스냅, 벽걸이(벽 클릭)·천장(펜던트)·가구 위(소품) 배치, 숫자 입력, 좌우 반전, 높이 조절, 나란히 복제(배열), 테이블 둘레 의자 자동 배치, 여러 개 정렬·균등 분배, 그룹, 고정(붙박이), 숨기기, 실행 취소 |

| **실제 제품 직접 추가** | 판매 페이지의 W×D×H, 형태 세부(좌면 높이·팔걸이·다리·서랍 수 등), 색·재질, 가격·링크 입력 → 같은 비례의 3D. 제조사 **3D 파일(GLB/GLTF/OBJ/FBX/STL)** 을 올리면 입력 치수에 정확히 맞춰 배치 |
| **후보 비교** | 같은 자리에서 다른 후보로 교체(뒤쪽 면 위치 유지), 후보(★) 목록, 상태(후보/확정/구매 완료/이미 있음) |
| **사람·동선** | 100점 사용성 점수, 생활 동선 6가지 시점 바로가기(현관·소파·침대·책상·주방·붙박이장), 아바타 키·자세, 가구별 '사람 앉혀/눕혀/세워 확인' |

| **버전** | 버전 복제·빈 버전(붙박이 유지), 메모, 자동 썸네일, 두 버전 비교표(비용·가구 수·바닥 점유·문제 수·차이 목록) |

| **무드보드** | 이미지 업로드·붙여넣기·끌어 놓기·링크, 메모·태그, 대표색 자동 추출 → 가구·벽 색 견본으로 사용, 액자로 벽에 걸기, 배치 화면 옆에 띄워 보기 |
| **예산** | 구매 목록(수량·참고가·상태·링크), 예산 대비, CSV 내보내기 |

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 핵심 로직 테스트 (vitest)
npm run build      # dist/ 정적 파일 — 어디든 올리면 동작
```

비밀번호·서버 저장까지 로컬에서 돌려 보려면 `APP_PASSWORD=아무거나 npm run dev` — `.local-store/` 폴더가 서버 저장소 대신 쓰여요.

## 배포 (Vercel)

이 저장소가 Vercel에 연결돼 있어 `main`에 올라가면 프로덕션, 다른 브랜치·PR은 미리보기로 자동 배포됩니다(`vercel.json`). 처음 한 번만 Vercel 대시보드에서:

1. **Storage → Create → Blob** — 접근 방식을 고르라고 하면 **Private**. 만든 뒤 이 프로젝트(2ndhome)에 **Connect** (환경 변수 `BLOB_READ_WRITE_TOKEN`이 자동으로 들어감)
2. **Settings → Environment Variables** — `APP_PASSWORD` = 들어갈 때 쓸 비밀번호 (Production·Preview 모두)
3. **Deployments → 최신 배포 → Redeploy** (환경 변수는 다시 배포해야 적용)

비밀번호가 없으면 사이트 전체가 "설정 필요" 화면으로 잠겨요. 저장소를 연결하기 전에는 들어갈 수는 있지만 이 기기에만 저장돼요.

### 무엇이 보호되나

- **사이트 전체**(페이지·스크립트·API)는 `middleware.ts`가 비밀번호 세션 없이는 내주지 않아요. 비밀번호를 모르는 사람은 로그인 화면만 보고, 그 화면에는 집에 대한 정보가 없어요.
- 세션은 HttpOnly 쿠키(120일). `APP_PASSWORD`를 바꾸면 모든 기기가 로그아웃돼요. 틀린 비밀번호는 응답을 늦춰 대입을 어렵게 하지만 횟수 제한은 없으니, 짧은 숫자보다 **긴 문장형 비밀번호**를 쓰세요.
- 프로젝트·이미지·3D 파일은 **비공개 Blob**에 저장돼 URL이 있어도 열리지 않고, 서버(`api/`)가 세션을 확인한 뒤에만 읽어요.
- **GitHub 저장소에는 집 데이터가 없어요** — 앱 코드, 일반 카탈로그, 샘플 원룸만 있어요. 집마다의 붙박이·구매 후보 목록은 그 프로젝트의 데이터(`customProducts`)로 함께 저장돼요. 커밋 기록에도 없어요. 그러니 저장소를 공개해도 집 내용은 드러나지 않아요. 다만 앞으로도 집 데이터(도면 이미지, 백업 파일 등)를 저장소에 커밋하지 마세요.

## 도면 실측

도면은 실측과 평면도 비율로 그린 추정값일 수 있어요. 천장 높이·창 높이·현관문 폭처럼 검사에 쓰이는 값은 실측해서 평면도/속성에서 고치면 모든 체크가 따라 바뀌어요. 집마다의 측정 메모는 그 프로젝트의 `info.planNote`에 저장돼 도면 편집 화면에 보여요.

## 카탈로그 치수에 대해

실제 제품 치수는 제조사 공개 사양 기준이며, 정확히 확인하지 못한 제품은 앱에서 **근사값** 표시가 붙습니다. 구매 전에는 판매처 상세 치수를 확인하고 다르면 속성에서 크기를 고치거나 ✎로 내 제품을 만드세요. 가격은 참고용입니다.

## 구조

```
src/
  types.ts            데이터 모델 (cm 단위, 평면 x/y → 3D x/z)
  catalog/            제품 카탈로그 · 분류 · 샘플 원룸
  models/             파라메트릭 3D 생성기 + 사람 모형
  lib/                기하 · 인체치수 · 분석(겹침/동선/체크) · 재질/텍스처 · 썸네일 · 3D 파일 로더
  store/              상태(zustand+immer, 되돌리기) · 저장(IndexedDB + 서버/계정 동기화, 3-way 병합)
  scene/              3D 뷰포트(R3F): 방, 가구, 상호작용, 오버레이
  ui/                 카탈로그 · 속성 · 체크 · 평면도 편집기 · 무드보드 · 비교/예산 · 제품 편집기
api/                  Vercel 함수: 로그인·세션·프로젝트·파일 (비밀번호 세션 확인 후 비공개 Blob 읽기/쓰기)
server/               비밀번호 세션(HMAC 쿠키) · 저장소 · 로그인 화면
middleware.ts         사이트 전체 비밀번호 잠금
tests/                핵심 로직 · 서버 · 병합 테스트
```
